Kekurangan yang Ditemukan
1. Masalah paling kritis: harga masih dipercaya dari frontend
Saat membuat booking, frontend mengirim:

totalPrice
roomPrice
roomType
Backend menyimpan nilai tersebut tanpa menghitung ulang harga berdasarkan:

Paket
Keberangkatan
Tipe kamar
Jumlah jamaah
Artinya, nilai harga dapat dimanipulasi dari browser. Ini berisiko menyebabkan:

Total booking tidak sesuai harga resmi
Harga kamar Rp0 tetap dapat dipilih
Booking dengan harga lebih rendah dari seharusnya
Data invoice dan laporan keuangan tidak akurat
Pada screenshot juga terlihat:

Single: Rp 0

Jika tipe kamar tersebut memang belum memiliki harga, seharusnya tidak ditampilkan sebagai pilihan aktif.

Prioritas: P0 — sangat kritis
2. Risiko overselling kuota
Backend memeriksa kuota terlebih dahulu, lalu mengurangi kuota dalam transaksi. Namun pengurangan kuota masih menggunakan pola:

remaining_quota = GREATEST(0, remaining_quota - jumlah)

Tanpa memastikan kuota masih mencukupi pada saat update.

Jika dua admin membuat booking bersamaan, keduanya bisa membaca kuota yang sama dan booking tetap diterima. Akibatnya:

Kuota bisa habis secara tidak akurat
Jumlah jamaah dapat melebihi kapasitas
remaining_quota hanya berhenti di angka 0 dan tidak menunjukkan overselling
Prioritas: P0 — sangat kritis
3. Status booking dan status pembayaran masih bercampur
Pada saat booking dibuat, status langsung di-set ke:

confirmed

Padahal pembayaran belum otomatis dicatat. Di daftar booking, status bisnis dan status pembayaran ditampilkan sebagai dua hal berbeda:

Status: Terkonfirmasi
Status Bayar: Belum
Ini memang memungkinkan secara teknis, tetapi alur bisnisnya belum jelas:

Apakah booking yang belum membayar sudah benar-benar mengunci kursi?
Berapa batas waktu pembayaran?
Kapan booking otomatis dibatalkan?
Apakah status confirmed berarti sudah disetujui atau sudah dibayar?
Apa perbedaan pending, draft, dan waiting_payment?
Selain itu, filter Menunggu Pembayaran dan Lunas terlihat berada di filter status booking, padahal status tersebut sebenarnya adalah status pembayaran. Ini berpotensi menghasilkan filter yang salah.

Prioritas: P0

Prioritas: P1
5. Tidak ada validasi hubungan paket dan keberangkatan di backend
Backend memvalidasi bahwa departureId ada, tetapi perlu dipastikan juga bahwa:

departure.packageId === packageId

Tanpa validasi tersebut, secara teori admin dapat mengirim kombinasi paket dan keberangkatan yang tidak sesuai.

Validasi yang sama diperlukan untuk:

Tipe kamar harus tersedia di keberangkatan tersebut
Harga kamar harus berasal dari keberangkatan tersebut
Agen harus aktif
Cabang harus valid
Keberangkatan harus berstatus aktif
Keberangkatan tidak boleh sudah lewat
Prioritas: P0/P1

Rencana Perbaikan
Fase 1 — Keamanan dan integritas data
1. Hitung ulang harga di backend
Backend menjadi sumber kebenaran harga.

Backend harus:

Mengambil departure berdasarkan departureId
Memastikan departure milik packageId
Mengambil harga kamar dari database
Menghitung total berdasarkan jumlah jamaah
Menolak tipe kamar yang tidak tersedia
Menolak harga Rp0 kecuali memang ditandai gratis
Mengabaikan totalPrice dari frontend atau hanya menggunakannya sebagai nilai pembanding
Hasil yang diharapkan:

Harga invoice selalu sama dengan harga database
Harga tidak dapat dimanipulasi dari browser
Kamar tanpa harga tidak dapat dipilih
2. Perbaiki penguncian kuota
Gunakan update atomik:

UPDATE package_departures
SET remaining_quota = remaining_quota - jumlah
WHERE id = departure_id
  AND remaining_quota >= jumlah
RETURNING remaining_quota

Jika tidak ada row yang dikembalikan:

Kuota tidak mencukupi

Hal ini harus diterapkan untuk:

Booking individu
Booking rombongan
Pindah keberangkatan
Pembatalan
Penghapusan booking
3. Tambahkan idempotency booking
Setiap submit booking harus memiliki idempotencyKey.

Contoh:

Frontend membuat UUID saat form dimulai
Backend menyimpan marker tersebut
Request dengan key yang sama tidak membuat booking baru
Backend mengembalikan booking yang sudah dibuat
